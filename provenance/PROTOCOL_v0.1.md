# Preregistered pilot protocol (v0.1, provisional until smoke checks)

- Use the official GSM8K main split. From 7,473 training rows, seed 42 selects 128 development-validation rows, 512 SFT rows and 256 separate RL rows. The remaining training rows are unused. The official 1,319-row test is not used for tuning. Do not view test outputs before the final evaluation.
- Compare E0/E1/E2/E3 on identical ordered validation IDs. Freeze prompt, parser, precision, seed and decoding cap before comparing. After choosing a recipe on validation, run the unchanged base and selected recipe on all official test rows; mark final test explicitly with `--split test --limit 1319 --final-test`. Report all attempted configurations, including failures and negative results.
- Primary accuracy: numeric exact match after extracting the final nonempty line (strict #### marker, explicit answer label, or standalone number). Secondary: strict #### numeric exact match. Do not extract arbitrary intermediate values. Fractions compare exactly, no floating-point tolerance. Invalid answers count as incorrect. Parser can reject correct answers with other formatting; report format and invalid rates. Use the same parser across arms.
- Report Wilson 95% intervals for descriptive accuracy, paired transitions, mean tokens, correct answers per 1,000 generated tokens, mean/p95 single-example latency, token-limit rate and peak allocated memory. Intervals do not correct for contamination or hyperparameter selection. No causal latency claims across hardware. Run repeat seeds if feasible and label single-seed results accordingly.
- SFT recipe: rank 8, alpha 16, attention projection adapters, dropout .05, 2e-4 learning rate, one epoch, batch 2 x accumulation 8, 768-token context. Filter overlong examples instead of truncating target answers; save omitted IDs. Completion-only masking is checked before training. No official test rows used by the trainer.
- RL plan: compare reward E2 = 1 for correct extracted numeric answer, 0 otherwise; E3 = correctness plus at most 0.05 valid-format bonus minus at most 0.15 excess-token penalty, only on correct answers. Default budget 128 tokens. All correct answers score above wrong answers. Rewards do not certify reasoning validity. Use token counts from actual completions, not character length. Both arms start from the same SFT checkpoint with equal update/generation budgets. GRPO trainer and Halo integration are future work.
- Potential issues: all-zero or equal group rewards, reward hacking, format-only gains, truncated completions, pretraining overlap, small validation set, single seed, and training runtime variability. Investigate examples gained/lost and malformed outputs, not just aggregate accuracy. Do not present a pilot as a production-grade or novel model.
